================================================================================
1. PROJECT OVERVIEW
================================================================================

The goal of Static-Documentation is to replace the existing paye-employers-documentation
GitHub Pages site, which currently serves a mix of PDFs, Excel spreadsheets, HTML pages,
and schema documentation (WSDL, XSD, JSON). The replacement project aims to:

  - Remove all PDFs, converting their content to rendered HTML pages
  - Retain Excel spreadsheets and schema documentation (WSDL, XSD, JSON/HTML API refs)
  - Style the new site using the Revenue Design System (REVDS)
  - Provide a WYSIWYG page builder for future content authoring and updates
  - Continue hosting on GitHub Pages (static files only - no server-side processing)

The migration pipeline converts PDFs to Markdown (via PyMuPDF scripts), then renders
the Markdown to HTML. Scripts are in migrationScripts/. A WYSIWYG page builder tool is
in create_page/.

================================================================================
2. WHAT IS WORKING WELL
================================================================================

  - PDF to Markdown to HTML pipeline: The core migration approach is sound. PyMuPDF
    extraction, heading detection, image extraction and link conversion are functional.

  - SPA router: The hash-based single-page router (assets/js/router.js) with
    sitemap.json as its data source is well-suited to GitHub Pages. No server
    configuration is needed.

  - Navigation hierarchy: The three-level card structure (Home > Section Card > Inner
    Page) maps cleanly to the source project PIT3/PIT4 folder structure.

  - Navbar with dropdowns: The context-sensitive navbar (flat links on home, dropdown
    with active state on inner pages) provides good wayfinding without a sidebar.

  - WYSIWYG page builder: The create_page tool gives content authors a path to create
    and update pages without writing HTML directly.

  - Underscore convention for sitemap utility groups: The _ prefix on non-content
    groups (_home_nav, _nav_groups) in sitemap.json prevents routing conflicts as the
    sitemap grows.

3.3 REVDS Styling - Angular Cannot Run on GitHub Pages
-------------------------------------------------------
The Revenue Design System (REVDS) is an Angular component library. GitHub Pages serves
only static files - it cannot execute an Angular build pipeline at deploy time. The REVDS
Angular components therefore cannot be used directly.

The current approach (Bootstrap 5 + custom SCSS using Revenue colour tokens) approximates
the REVDS visual style but does not use the actual REVDS component CSS. This means any
updates to REVDS will not automatically propagate to this site.

3.4 Migration Script Limitations
----------------------------------
The pdfToMarkdown.py script has several issues that affect output quality:

  - Image paths are fragile: The script constructs image paths relative to the script
    directory using os.path.dirname(__file__). This breaks when the script is run from
    a different working directory.

  - Heading detection is unreliable: Any uppercase text is treated as a heading. Many
    PDFs use all-caps for non-heading text (e.g. labels, form fields, table headers).

  - Output location: Markdown files and image folders are written to migrationScripts/
    alongside the source PDFs, not to the templates/ directory where they are needed.

  - No table detection: Tab-separated detection covers only a subset of PDF table
    layouts; most complex tables in the source documents will not convert correctly.
